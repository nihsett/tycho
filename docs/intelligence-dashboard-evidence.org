*** The read-only boundary is structural, not a convention
=CloudReadSource= constructs its own BigQuery and Firestore clients rather than
borrowing =pipeline.cloud.CloudBackend=, so the object never holds a Cloud
Storage or Pub/Sub client at all. Its public surface is exactly nine methods:
=list_claims=, =get_claim=, =get_delta=, =list_canonical_deltas=,
=get_observation=, =watcher_activity=, =strategy_sessions=,
=get_strategy_session=, =get_brief=.

A test asserts that set exactly, so adding a write method to the source is a
test failure rather than a silent capability grant. A second test drives a full
read pass — health, overview, timeline, provenance, latest session, activity —
through a recording fake and asserts that no forbidden method name
(=create_claim=, =insert_delta=, =publish_delta=, =get_raw=, =get_audit_delta=,
=commit_strategy_session=, …) is ever reached.

Every Delta query names =tycho.deltas= and pins
=schema_version = 'delta@2'=; a test counts the Delta queries in the module and
asserts each one carries that constraint, and another asserts no query line
mentions the archive.

*** Exact claim versions
=GET /api/claims/{claim_id}/versions/{version}/provenance= resolves the exact
version. The current version returns the live claim; an earlier version is
reconstructed from the claim's embedded history and reported with
=exact_version: false= plus a reconstruction note; a version that never existed
is a =404=. The response never contains =gs://=, =content_ref=, or
=content_hash= — a test asserts that on the serialized payload.

*** Derived agent activity
The council's in-flight events are not persisted, so the dashboard does not
pretend to replay them. It reconstructs the fixed workflow's structural timeline
from the session record and marks every event =derived: true=; the UI says so in
plain language.

A rejection reason is reduced to a deterministic *class* before it becomes an
event — =entity_diversity=, =source_diversity=, =conclusion_language=,
=stale_premise=, =premise_version=, =challenger=, and so on. A test takes every
piece of governed prose the fixture session holds (card statements, rationales,
competing explanations, falsifiers, rejection reasons, claim statements and
rationales, Delta summaries, grounded quotes, and the brief markdown) and proves
none of it occurs anywhere in any derived event. The full reasons are shown
where they belong: in the brief's collapsed =Rejected by Challenger= section.

** Frontend
=dashboard/frontend/=, React 19.2.8 + TypeScript 5.9.3 + Vite 8.2.2, tested with
Vitest 4.1.11 and Testing Library 16.3.2 under jsdom 30.0.1. Every dependency is
pinned to an exact version in =package.json= with a committed
=package-lock.json=; =npm audit= reports 0 vulnerabilities. No UI framework: about 400 lines of hand-written CSS with
one custom property per lifecycle state.

Components are named after product concepts, as the handoff asks:
=FleetHealthBar=, =CompetitorGrid=, =CompetitorCard=, =BeliefTimeline=,
=StrategyBrief=, =StrategyCard=, =AgentActivityTimeline=, =ProvenanceDrawer=,
=RunStrategyButton=. There is one typed API client (=lib/api.ts=), and no =any=
in the event or provenance types (=lib/types.ts=).

The SSE enum is closed:
=run_started|agent_started|agent_completed|card_rejected|brief_completed|run_failed|heartbeat=.
=parseEvent= refuses anything outside it.

*** Untrusted text stays text
There is no =dangerouslySetInnerHTML= anywhere in the app. =lib/markdown.ts=
parses a bounded subset — headings, paragraphs, bullets, bold, code — strips
=<= and =>=, flattens any external Markdown link to its label, and keeps only
internal claim-provenance links of the exact shape the citation callback
produces. Grounded quotes render as text nodes inside a =blockquote=.

Borrowed from the ADK Deep Search sample: session-aware SSE consumption, a
progressive activity timeline, and clear loading/empty/error states. Not
borrowed: console logging of complete SSE events, rendering function arguments
or responses, a chat transcript, website-count gimmicks, or its styling.

through this tooling: =grant-viewer= refuses =allUsers= and
=allAuthenticatedUsers= outright, and both the deploy readback and the grant
path re-read the policy and fail closed on a public member.

Access is explicit and per identity. Currently exactly one invoker:
=user:nihsett@gmail.com=.

IAP was not used: it requires an external HTTPS load balancer, which the handoff
allows skipping in favour of "explicit demo-user access". The documented access

** The deployment tool cannot touch the analyst or strategy path
Every shell-out goes through one =run()= wrapper that calls =guard_command()=
first. It reuses =PROTECTED_RESOURCES= from =infra/deploy_strategy_council.py=
and adds =tycho-strategy-dispatcher=, =tycho-strategy-weekly=, the Strategy
Council Runtime display name, and =reasoningEngines=.

A gcloud *target* is a positional argument, so the guard inspects positionals
and any flag whose value is exactly a protected name. That distinction matters:
the dashboard legitimately passes the strategy dispatcher's URL as an
environment variable, and that must not read as an attempt to modify it, while
=--service=tycho-nightly= still must.

Exactly one write against a protected resource is permitted, and it is matched
structurally rather than by intent: =gcloud run services add-iam-policy-binding
tycho-strategy-dispatcher= with =--role=roles/run.invoker= and a single
=--member= that is the dashboard's own service account. A wider role, a
different member, a removal, or a different verb is refused. Thirty tests assert
the refusals, the permitted reads, and this one exemption.

* Demo sequence
Six steps, none of which depends on new external data arriving.

1. *Landing.* Four fleet-health pills and four competitor cards, each with its
   latest meaningful canonical change, its active verified fact count, and when
   it was last observed and verified.
2. *Open a competitor.* Click a card; the belief timeline filters to that
   entity. Every event pins =(claim_id, version)=. Retirement events carry the
   governed reason recorded during the legacy-evidence migration.
3. *Open the latest Strategy Brief.* The stored brief for ISO week 2026-W34,
   with its session ID, period, card counts, pinned claim-version count, and
   context size.
4. *Expand =Rejected by Challenger=.* Both production cards, with the
   deterministic reasons Python generated: one failed only the
   conclusion-language policy despite clearing both diversity rules; the other
   failed entity diversity, source-family diversity after mirrored-evidence
   normalization, *and* conclusion language.
5. *Click Run Strategy Session.* The stream opens, heartbeats appear while the
   dispatcher works, and the session comes back through the lease with no model
   call. The activity timeline then names the workflow's agents.
6. *Open the provenance drawer.* From any claim or premise chip: current claim
   and exact version, lifecycle links, the canonical Delta's category, source,
   and grounded quote, the before/after observation IDs, and the configured
   source URL.
