* Cutover partial-failure safety fix (2026-08-26)
=run_cutover()= previously resumed Cloud Scheduler unconditionally in its
=finally= block. That is unsafe in exactly one case: the old canonical table is
successfully renamed to the audit name and renaming the candidate to =deltas=
then fails. Resuming there would let scheduled acquisition run while canonical
=deltas= is absent.

The corrected rule reads the real physical table names instead of trusting how
far the cutover believed it got:
- resume after a successful swap and full read-back;
- resume when the archive rename did not commit and the original =deltas= table
  is still authoritative — this is the original streaming-blocker case;
- otherwise leave Scheduler paused, because canonical =deltas= is absent or
  unverified. An ambiguous rename failure therefore fails closed.

A paused partial state writes =scheduler_left_paused=, the exact
=resumable_state= physical-table report, and the documented =resume_command=
into the evidence file, and prints the same bounded report on stderr. Evidence
is written on both success and failure.

Regression coverage in =tests/test_migration_tools.py=:
- =test_cutover_resumes_scheduler_when_streaming_blocks_the_first_rename=;
- =test_cutover_leaves_scheduler_paused_when_second_rename_fails=;
- =test_partial_cutover_state_remains_resumable=.

The suite is =95 passed=. Ruff is clean over every source package; the only
three repository Ruff findings are in the untracked =docs/diagrams/hero.py=,
