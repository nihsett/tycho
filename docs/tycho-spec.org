* Purpose of this document
This is the single source of truth for building Tycho. Every agent session
MUST read this file before writing code. Code that contradicts this spec is
wrong; if the spec is wrong, update the spec first, then the code.

* One-line summary
A fleet of agents watches competitor entities (GitHub, websites, RSS, search),
records immutable observations, and generates grounded semantic deltas over
bounded before/after observation pairs. It maintains a versioned, evidenced,
supersedable store of *claims* — a living theory of each competitor. Consumers
(weekly brief, Q&A agent) read only claims, never raw data.

* Core principles
1. Observations are immutable facts. Claims are mutable beliefs with history.
   Facts accumulate; beliefs revise. (BigQuery = what happened. Firestore =
   what we believe.)
2. Acquisition and hash gating are deterministic. Every canonical Delta,
   including noise, is generated by Gemini over a bounded observation pair;
   every model change must include exact source quotes and pass deterministic
   Python validation. The model never rewrites or replaces immutable
   observations. The retired mechanical delta@1 format is migration/audit
   evidence only, never a canonical or production authority.
3. Every claim cites evidence (>=1 delta). Inference claims cite >=2 evidence
   entries from DIFFERENT sources.
4. Correction happens only via supersession, never in-place edits.
   Supersession is publish-before-retire (crash-safe: duplicates possible,
   silent loss impossible).
5. Demotion rule: the analyst cannot retire or lower confidence of a
   confirmed+critical claim using evidence from the same delta batch it is
   currently processing, unless evidence is from the entity's own primary
   source. Instead it flags the claim disputed.
6. Specialization lives in data (operational claims per source), not code.
   Adapters are generic per source TYPE; per-source quirks are learned and
   stored as operational claims, injected before fetch.
7. Append-only wherever possible. Noise is recorded, not discarded silently.
8. Quarantine path exists from day one: fetched content that contains
   instruction-like text aimed at LLMs is stored but never fed to the analyst.

* Storage layout
| Data          | Store         | Mutability            |
|---------------+---------------+-----------------------|
| observations  | BigQuery      | append-only           |
| canonical deltas | BigQuery (tycho.deltas) | append-only, strict delta@2 |
| Delta audit log | BigQuery (tycho.delta_audit_log_20260826) | immutable migration evidence |
| raw payloads  | Cloud Storage | write-once            |
| claims        | Firestore     | versioned, lifecycle  |
| analyst leases| Firestore     | transactional delivery identity |
| Delta generation runs/leases | Firestore | retryable model-attempt identity |
| strategy sessions | Firestore | write-once audit of one bounded session |
| strategy leases | Firestore   | transactional (period, strategy_version) identity |
| briefs        | Firestore     | write-once render     |
| receipts      | Firestore     | append-only           |
| config        | repo (YAML)   | git-versioned         |

BigQuery tables partitioned by fetched_at / computed_at.
No primary keys in BigQuery; obs_id/delta_id are ULIDs, unique by convention.

** Local/cloud parity
While cloud provisioning is unavailable, the fleet MUST accrue real tenure in
local mode rather than wait. Local mode mirrors the same store interfaces:
- SQLite stores immutable observations/deltas plus versioned claims/receipts.
- The filesystem stores write-once raw payloads.
- A durable SQLite outbox replaces Pub/Sub; analyst delivery is idempotent and
  retried after restart.
- Transactional local analyst, Delta-generation, and strategy-session leases
  mirror the cloud delivery identities, so concurrent or replayed deliveries
  cannot start duplicate model calls.
- Strategy sessions and briefs persist in SQLite with the same write-once
  semantics and the same method signatures as the Firestore backend.
- Failed/expired semantic generation pairs remain retryable before a later fetch;
  a valid noise result completes the pair without entering the outbox.
- IDs, source timestamps, evidence links, lifecycle status, and raw hashes are
  identical to cloud mode. Local mode does not invent deltas during bootstrap.
- Backfill is idempotent and preserves those IDs/timestamps while rewriting only
  local raw content_ref values to their uploaded gs:// locations.
GCP remains the production store. Local consumers obey the same claims-only
boundary and quarantine rules as cloud consumers.

* Data model
** Observation (BigQuery: observations)
#+begin_src json
{
  "obs_id":      "obs_01J...",
  "entity":      "mem0",
  "source":      "github_releases",
  "kind":        "structured|text|image",
  "fetched_at":  "2026-08-20T02:00:00Z",
  "content_ref": "gs://tycho-raw/mem0/github_releases/01J....json",
  "content_hash":"sha256:...",
  "adapter_ver": "github@1",
  "status":      "ok|fetch_failed|quarantined"
}
#+end_src
Rules:
- Raw content never in the row; Cloud Storage pointer + sha256 hash.
- Same content_hash as previous observation of same (entity, source) =>
  pipeline stops (bump last_verified_at on claims in affected scopes).
- Re-fetch is a new row. Never update.
- fetch_failed is a first-class row; 3 consecutive failures for a source
  triggers the self-repair flow (investigate -> operational claim).

** Delta (BigQuery: tycho.deltas)
=delta@1= is retired from the canonical domain. Existing mechanical rows are
preserved only in the immutable migration audit table
=tycho.delta_audit_log_20260826= and are never returned by normal application
reads. New production rows and all historical replacements are the one strict
canonical =delta@2= domain object:
#+begin_src json
{
  "schema_version": "delta@2",
  "delta_id": "dlt_01J...",
  "comparison_id": "sha256:<obs_before|obs_after|generated_by|prompt_version>",
  "entity": "pi",
  "source": "github_releases",
  "obs_before": "obs_01H...",
  "obs_after": "obs_01J...",
  "computed_at": "2026-08-25T02:03:11Z",
  "diff_kind": "semantic",
  "generated_by": "gemini-3.7-flash@semantic-differ-1",
  "prompt_version": "semantic-delta@2",
  "changes": [
    {
      "category": "capability",
      "scope": "product/capabilities",
      "statement": "Pi added optional native PowerShell execution on Windows.",
      "before": null,
      "after": "Native PowerShell execution is available as an optional tool.",
      "evidence_before": null,
      "evidence_after": {
        "obs_id": "obs_01J...",
        "quote": "Added an optional `powershell` tool for Windows."
      }
    }
  ],
  "summary": "Pi added native PowerShell execution.",
  "triage": "meaningful",
  "triage_reason": "The release introduces a durable user-facing capability.",
  "triage_by": "gemini-3.7-flash@semantic-differ-1",
  "routed_to": ["product/capabilities"]
}
#+end_src

Categories are the closed enum =capability=, =deprecation=, =pricing=,
=policy=, =integration=, =availability=, =positioning=, =reliability=, or
=other=. Scopes are the existing fixed ontology branches. A meaningful Delta
has 1–8 changes and at least one scope. A noise Delta has zero changes and zero
scopes, but a non-empty reason. Every meaningful change has grounded
evidence_after whose obs_id is obs_after; any evidence_before obs_id is
obs_before. Statements, summaries, reasons, and quotes have explicit bounded
lengths. Unknown fields and enum values are rejected.

The Python validator derives =routed_to= as the unique union of accepted
change scopes. It rejects duplicate statements/evidence, version/tag
publication-only statements, and removal/deprecation inferred only from absence
in a bounded snapshot. Each quote must occur inside one actual source string
field; joining unrelated fields, JSON keys, or serialized object boundaries
cannot manufacture evidence. It does not require or fabricate a path for
delta@2; =path= is nullable and legacy-only for delta@1. Legacy =before= and
=after= JSON values remain readable during migration.

The semantic differ is entity-scoped as well as source-grounded. On a broad or
mixed-product changelog, it reports only changes whose quoted content or
unambiguous enclosing section concerns the configured entity or one of that
entity's own components. Changes concerning only a sibling or parent product
are omitted; if no entity-relevant durable change remains, the result is noise.
A corporate brand or shared publishing page is not evidence that every entry
belongs to the monitored entity.

A provider, schema, grounding, boundary, enum, relevance, or policy failure
creates no Delta and advances no observation transition. The pair remains
retryable. Historical replay/import is governed, resumable, and non-publishing;
it never emits Pub/Sub traffic or mutates claims implicitly.

The raw observations are the only source evidence. A semantic differ failure,
malformed response, grounding failure, or oversized pair creates no Delta and
never advances the transition silently. Valid noise is appended for audit and
cost measurement but is never published to Pub/Sub or sent to the analyst.

** Claim (Firestore: claims/{claim_id})
#+begin_src json
{
  "claim_id":    "clm_01J...",
  "entity":      "mem0",
  "scope":       "pricing",
  "class":       "fact|inference|operational",
  "inference_kind": null,
  "statement":   "Pro plan is $79/mo (was $49 until 2026-08-19); free tier halved to 5k memories.",
  "rationale":   "Aggressive monetization shift; likely margin pressure or upmarket move.",
  "confidence":  "confirmed|likely|speculative",
  "severity":    "critical|notable|context",
  "evidence":    [ { "delta_id": "dlt_01J...", "source": "website_pricing", "note": "price table diff" } ],
  "status":      "active|superseded|retired",
  "superseded_by": null,
  "supersedes":  "clm_01H...",
  "disputes":    null,
  "version":     3,
  "created_at":  "...",
  "last_verified_at": "2026-08-20T02:05:00Z",
  "created_by":  "analyst@1",
  "history":     []
}
#+end_src
Rules:
- entity may be a canonical entity key or "market" (cross-entity claims).
- scope is an ontology path (see config). Unknown scope = hard reject.
- Every evidence entry records its delta_id, source, and note so source
  diversity can be validated without querying another document.
- Evidence bars by class:
  - fact: >=1 delta from the entity's own primary source. confidence=confirmed.
  - inference: >=2 evidence entries from DIFFERENT sources. confidence in
    {likely, speculative}. The sole exception is a dispute inference: when
    disputes is set, exactly one third-party signal is sufficient because the
    claim asserts that a conflicting signal exists, not that the signal is true.
    The disputes link identifies the established claim it conflicts with.
  - inference_kind is required on inference claims: present_state or
    intent_or_future. intent_or_future confidence is clamped to speculative in
    the tool layer regardless of source count. Non-inference claims set it null.
  - operational: scoped under sources/<source>; injected into watchers
    pre-fetch, never into consumer answers.
- confidence (how sure, evidence-driven) and severity (how much it matters,
  impact-driven) are orthogonal enums. speculative+critical = alert sweet spot.
- Supersession: write new claim with supersedes -> flip old to superseded
  with superseded_by. Publish-before-retire. Doubly-linked chain = UI timeline.
- disputes is an optional link on speculative inference claims. A dispute claim
  remains separate from the established active claim; the UI derives its
  disputed badge from active inbound disputes links.
- A dispute claim inherits severity from its target. speculative+critical claim
  creation emits an immediate alert. Resolving/superseding the dispute clears
  the target's badge without mutating the target.
- Demotion rule as in Core principles #5.
- last_verified_at: bumped by no-change re-fetches of relevant sources.
  Staleness thresholds per branch (config). Stale claims greyed in UI,
  flagged in brief, voiced by Q&A agent ("as of N days ago...").
- history embedded in doc, capped ~20 versions (archive overflow to BigQuery).
- Statements are self-contained, dated, quantified. Rationale answers "why
  would the user care". severity=critical means "affects user's pricing or
  positioning decisions this quarter".

* Pipeline stages
1. Acquire (deterministic): Scheduler fires -> Cloud Run job -> adapter fetch
   -> immutable raw payload in Cloud Storage -> immutable Observation in
   BigQuery. Operational claims are read and applied BEFORE fetch.
2. Hash gate: same hash as the last clean observation -> bump relevant
   last_verified_at clocks and stop before a model call.
3. Comparison preparation: for a changed clean pair, decode normalized GitHub
   release fields or canonical webpage title/sections. Keep the complete pair
   bounded; do not run the legacy path/hunk differ first.
4. Semantic differ: Cloud Run calls only =gemini-3.7-flash= through the
   Vertex/Agent Platform ADC client at the =global= endpoint with LOW thinking,
   strict JSON, exact source-quote requirements, and entity-relevance filtering
   for broad or mixed-product sources.
5. Python validation: Pydantic proposal schema, source-side grounding,
   observation-ID checks, duplicate/bounds/policy checks, and routed-scope
   derivation. Any failure records a failed generation run and advances nothing.
6. Append valid meaningful or noise =delta@2= to the canonical BigQuery table;
   publish only meaningful rows to the existing =tycho-deltas= topic.
7. Analyst (Gemini via ADK): per meaningful Delta, run the unchanged Decision
   Procedure through the existing authenticated dispatcher and Agent Runtime.
8. Consumers: brief-writer (weekly schedule), Q&A agent (on demand), alerts
   (severity=critical claims -> immediate Slack).

Production acquisition has one mode: =TYCHO_DIFFER_MODE=semantic= (the
runtime default and only cloud-deploy choice). Gemini is the only Delta
producer. There is no mechanical fallback after a semantic failure: the failed
pair records a retryable generation attempt and advances nothing. The retired
Python differ may remain only behind an explicit local/test or archive-decoding
guard that cloud startup rejects. Operational rollback is pause/retry or a
previous known-good semantic image; it never re-enables Python Delta generation.

* Semantic generation runs and retries
A historical backfill uses traffic type =historical_backfill=. It uses the same
lease identity and retry state machine as live acquisition, but inserts only
validated delta@2 rows and never publishes or invokes the analyst. Saved replay
imports record historical evidence rather than pretending a new provider call.

A generation lease is keyed by =(obs_before, obs_after, generated_by,
prompt_version)=. One active unexpired lease owns one model attempt; a completed
lease returns its existing outcome; failed or expired attempts increment and
retry. Run records contain only observation IDs/hashes, traffic type, model and
prompt versions, token counts, latency, estimated cost, validation result,
outcome, and bounded error metadata. They never contain prompt/response text or
raw source content. At acquisition startup, failed/expired pairs are retried
from immutable stored observations before new content is fetched. A noise Delta
completes the pair without Pub/Sub publication. A failed run never creates a
fake Delta and never silently advances the observation transition.

* Analyst decision procedure
This section is the analyst's system prompt AND the regression test spec.

** Input envelope
#+begin_src
{ delta,             // full delta record
  scope_claims[],    // active claims in routed_to branches for this entity
  entity_context,    // name, aliases, one-line description from config
  market_claims[] }  // active market/ claims touching same branches
#+end_src

** Tools
- create_claim(...)
- supersede_claim(old_id, new_claim)
- adjust_confidence(claim_id, new_level, evidence)
- bump_verified(claim_id)
- no_action(reason)
Every invocation must cite >=1 delta_id. The TOOL LAYER (pipeline/claims.py),
not the prompt, hard-rejects violations: evidence bars, demotion rule,
unknown scopes, non-enum values. The serialized envelope is also subject to a
conservative 200 KB / roughly 50,000-token budget; an oversized envelope is
recorded as a failed analyst run and is never sent to the model.

** Ordered checks (run in order, stop at first match)
1. Dispute resolution: an entity-primary delta resolves an active dispute ->
   supersede the dispute with the primary-source fact. The established claim
   remains active; with no active inbound dispute, its UI badge clears.
2. Redundancy: an active claim already states this -> bump_verified. Done.
3. Contradiction:
   - Entity-primary evidence -> draft replacement and supersede_claim. Never
     edit in place.
   - Non-primary evidence -> create_claim(class=inference,
     inference_kind=present_state|intent_or_future, confidence=speculative,
     severity inherited from target, disputes=<target claim>). Evidence is the
     current conflicting delta alone. Keep the target active. Never silently
     no_action a contradiction of a critical claim.
4. Novel fact: new info from the entity's own artifact -> create_claim
   (class=fact, confidence=confirmed). Statement contains concrete
   before/after and date.
5. Inference opportunity: combined with other active claims from DIFFERENT
   sources, a pattern emerges -> create_claim(class=inference,
   confidence=likely|speculative). Rationale names the pattern. Claims about
   intent or future action are always speculative.
6. Operational learning: delta reveals source weirdness (moved URL, format
   change, stale extract_hint) -> create_claim(class=operational,
   scope=sources/<source>).
7. Else: no_action(reason). Legitimate and logged. An analyst that never
   no-actions is hallucinating significance.

** Worked examples (implement as regression tests)
1. Fact: pricing delta $49->$79 -> check 4 -> fact/confirmed/critical,
   scope pricing.
2. Supersession: later primary delta $79->$59 -> check 3 primary branch ->
   supersede previous; new claim's rationale notes the reversal.
3. Fusion: delta = 3 Rust job postings (team); scope_claims include inference
   "perf complaints across community/issues" -> check 5 -> inference with
   inference_kind=intent_or_future, clamped speculative: "likely perf-focused
   rewrite", evidence from different sources.
4. No-action: blog delta = new tutorial, no strategic content -> check 7,
   no_action("content marketing, no positioning change").
5. Third-party contradiction: single search-result delta claims "Zep shutting
   down" vs confirmed+critical traction claim -> check 3 non-primary branch ->
   create inference/speculative/critical with disputes=<traction claim> and the
   search delta as its sole evidence; alert; do NOT supersede target.
6. Dispute resolution: Zep's primary blog says "we're not going anywhere" ->
   check 1 -> supersede the dispute with the confirmed primary-source fact.
   The established traction claim remains active and its disputed badge clears.

* Strategy council (Strategist, Challenger, Brief Writer)
Three named ADK agents run over governed memory in one bounded, non-looping
workflow. Together with the Analyst they are Tycho's four-agent fleet.

A session answers exactly one fixed question:

#+begin_quote
What materially changed across the monitored coding-agent market, why does it
matter, and what evidence could change this conclusion?
#+end_quote

The dispatcher accepts a bounded period and a request ID. It accepts no prompt
text, so the question is a constant and not an input. Two triggers share the
same code path: the weekly Cloud Scheduler session and the authenticated
dashboard =Run Strategy Session= action.

** Workflow
#+begin_example
bounded context builder (Python)
  -> tycho_strategist
  -> hard proposal validation
  -> tycho_challenger
  -> hard challenge gate
  -> tycho_brief_writer
  -> citation validation + write-once persistence
#+end_example

There is exactly one Strategist pass and one Challenger pass. There is no
open-ended loop in v1: a model cannot talk its way past a failed check.

The deployed Runtime root is a deterministic =BaseAgent= wrapper, never a
=SequentialAgent= over the three =LlmAgent= objects. A raw sequence would run
them back to back with no Python between them, which is precisely where the
evidence gates live. The wrapper parses only a bounded request, builds its
backend per request, calls the governed workflow, and returns only IDs, state,
and counts.

Lease acquisition and creation of the running session are one atomic store
operation, so a duplicate trigger can never see an active lease with no readable
session: it either wins and creates both, or loses and reads the winner's
running session. The running session starts with an empty manifest and zero
metrics; the completed document carries the final context.

The brief, the session's terminal state, and the lease release are likewise one
atomic operation, and that commit requires the committing session to still hold
an =active= lease it owns. A crash cannot leave a stored brief whose session is
still running, which is the state that would permanently block retries for that
period, and a session whose lease was reclaimed cannot publish. Brief IDs carry
a per-session discriminator so a retry over the same week cannot collide with an
abandoned attempt's write-once brief.

Because the placeholder session is durable before the context is built, a
context failure is recorded as a failed session with sanitized metadata rather
than vanishing.

** What the session may read
Governed memory only: active non-operational claims whose evidence resolves
entirely to canonical Gemini =delta@2= rows, their exact versions and staleness,
period claim activity, and deterministic metrics computed from canonical Deltas.
No web search, no raw GCS snapshot, no Memory Bank. New external evidence enters
through acquisition first. Every metric carries the Delta IDs it was computed
from. Context is capped by explicit bytes and estimated tokens; an oversized
session fails durably before any model call rather than truncating evidence.

** Evidence rules (Python is the final authority)
The model proposes; =pipeline/strategy_evidence.py= decides. A card passes only
when every rule holds:
1. Every premise claim exists, is active, and matches the exact cited version.
2. Every premise rests only on canonical Gemini =delta@2= rows that are
   =meaningful=, whose entity matches the claim's entity, and whose source
   matches the source recorded on the claim's evidence entry. Noise Deltas are
   audit and cost evidence, never premises. The context builder applies the same
   rule, so a claim is never admitted on evidence a card would be rejected for.
3. At least two distinct entities are represented.
4. At least two distinct source families are represented.
5. Source families are normalized deterministically. One vendor's own release
   channels — GitHub releases, its mirrored changelog, its blog feed — are one
   family. Evidence whose grounded quotes are textually identical after
   normalization collapses into one witness even across families, so republished
   official text can never read as independent corroboration.
6. A stale premise (under =tycho.yaml= thresholds) is admissible only when the
   card explicitly labels it as a limitation naming that claim, and confidence
   is speculative.
7. The conclusion may not assert removal, causation, intent, market leadership,
   or future action without evidence that explicitly supports it. In v1 only
   removal can be supported, and only by a =deprecation= change in a premise
   Delta; causation, intent, leadership, and prediction are rejected outright.
8. Confidence never exceeds the weakest required premise and is never
   =confirmed=. A confirmed premise licenses at most =likely=.
9. At most three cards survive one session.
10. No model-generated citation, claim ID, version, Delta ID, metric, or count
    is accepted without store lookup or recomputation. The Strategist emits only
    =(claim_id, claim_version)= pairs; premise Delta IDs, entities, scopes, and
    source families are all recomputed in Python.

Model agreement is not evidence. A Challenger =pass= is quality control: it can
only reject, never revive a card that failed a hard check. Cards rejected by
either gate stay visible in the session audit and never reach the brief.

** Cards, sessions, and briefs
Strategy cards stay =present_state= while Tycho's only source families are
duplicated official release channels. A passed card is persisted in its session,
not promoted into a =Claim=; promotion to an inference claim would be a separate
explicitly approved action under the existing evidence bars.

Sessions and briefs are write-once. A session is created =running= and moves to
exactly one terminal state; a rerun creates a new session. The lease identity is
=(period_from, period_to, strategy_version)=, so a duplicate trigger returns the
existing session without a model call, while a failed or expired session stays
retryable.

A brief cites =(claim_id, version)= through machine markers of the form
=<claim id="clm_..." version="3"/>=, which a deterministic callback replaces with
dashboard links. A brief never cites a URL. An unknown, malformed, or unpinned
citation fails the run. Zero passed cards is a valid, valuable result: the
session stores an empty brief stating that no defensible cross-entity pattern
survived validation.

** Redaction
Persisted strategy events and exported traces carry structure only — session ID,
agent name, state, card counts, rejection counts, claim IDs/versions, run IDs,
token counts, latency. Prompts, model responses, claim statements, rationales,
quotes, and brief prose are excluded by construction from an allowlist.

Durable error fields never store =str(exception)=. Pydantic's =ValidationError=
renders =input_value=, so a malformed model response or a grounded quote could
otherwise reach a session, lease, or log. One sanitizer reduces every failure to
a stage, an exception class name, and a curated reason; an unrecognised class
collapses to a generic reason rather than falling through to its own text.

   Enums for every closed field. No free-text where an enum is specified.

   requires >=2 evidence entries with distinct sources; ULID-shaped ids;
   ISO timestamps.
   Cross-document lifecycle logic NOT in models: implement publish-before-
   retire supersession, demotion rule, delivery dedup as named functions in
   pipeline/claims.py with docstrings quoting the rule from this spec.

4. Write pytest: every fixture loads, validates against its model,
   round-trips (serialize -> parse -> key fields survive). Task is not done
   until this passes.

   Cloud Scheduler -> Cloud Run acquisition -> deterministic adapter -> raw
   Observation -> hash gate -> bounded Gemini semantic differ -> Python
   validation -> delta@2 -> existing Pub/Sub -> existing analyst Runtime.
   Operational rollback pauses/retries or restores a prior semantic image/table
   checkpoint; it never enables Python Delta generation or replays historical
   output into live claims.
6. Python everywhere. ADK (Python) for agents. Google Cloud client libraries.
   No other languages, no frameworks beyond what is needed.

- No multi-tenancy. No auth. No more than 4 entities, 4 source types.
