* What was built
** Contracts
- =schemas/strategy.py= — =PremiseReference=, =StrategyCard=, =ChallengeResult=,
  =StrategySession=, =ManifestEntry=, =MetricEvidence=, =SessionMetrics=, plus
  the model-facing draft schemas =StrategyCardDraft=, =StrategyProposal=, and
  =BriefDraft=. All IDs are ULID-shaped and pattern-bounded, all free text has an
  explicit maximum length, and every model rejects unknown fields.
- =schemas/brief.py= — =Brief= gains =strategy_session_id= and
  =strategy_card_ids=. Analyst-era briefs leave both unset and still validate.

The draft schemas the agents emit carry *no* Delta IDs, entities, scopes, or
counts. Those are recomputed in Python, which is what makes handoff rule 10
structural rather than a prompt instruction.

** Deterministic rules
- =pipeline/strategy_evidence.py= — premise resolution against the store,
  canonical-v2 enforcement, source-family normalization, conclusion-language
  policy, staleness, and the confidence ceiling.
- =pipeline/strategy_context.py= — the bounded context manifest, deterministic
  selection, period metrics carrying their contributing Delta IDs, and the
  byte/token budget.
- =pipeline/strategy_lease.py= — the =(period_from, period_to, strategy_version)=
  lease identity shared by both backends.

** Source-family normalization
One entity's own publication channels collapse to one family:
=github_releases=, =website_changelog=, and =blog_rss= all map to
=<entity>/official_release=; =website_pricing= and =x_account= map to their own
first-party families; anything else is =<entity>/independent:<source>=.

On top of that, two Deltas whose grounded quotes are byte-identical after
whitespace/case normalization collapse into one witness *even across families*.
That second rule is what makes republished official text unable to masquerade as
independent corroboration — the exact =cross_source_mirrored_evidence= pattern
the read-only candidate audit found 13 times for =claude_code= between
=github_releases= and =website_changelog=.

** Conclusion-language policy
Five families are detected deterministically: removal, causation, intent,
leadership, and future action. In v1 only *removal* can be evidenced, and only by
a =deprecation= change in a premise Delta. Causation, intent, leadership, and
prediction are rejected outright, because Tycho's evidence cannot support them.

** Agents
| Agent | Name | Output schema | Tools |
|-------+------+---------------+-------|
| Strategist | =tycho_strategist= | =StrategyProposal= | none |
| Challenger | =tycho_challenger= | =ChallengeResult= | none |
| Brief Writer | =tycho_brief_writer= | =BriefDraft= | none |

Each is a strict-structured =LlmAgent= with =include_contents="none"= and both
transfer paths disallowed. ADK's task mode attaches only its own internal
finish-task tool; there is no search, storage, fetch, memory, or claim-mutation
tool on any of them.

** Governed Runtime entrypoint
The deployed root agent is =StrategyCouncilAgent=, a deterministic =BaseAgent=
wrapper following the =runtime_agent/agent.py= pattern. It is deliberately *not*
a =SequentialAgent= over the three =LlmAgent= objects: that shape would run them
back to back with no Python between them, which is exactly where every hard
evidence check lives.

The wrapper:
- parses only a bounded =StrategyRequest= (period plus request ID; any extra
  field is rejected, so prompt text cannot reach an agent);
- constructs =CloudBackend= and the config inside the request, holding no live
  client in the deployed object;
- calls =run_strategy_session=, so the three named agents are invoked only
  through the governed workflow;
- returns only session ID, strategy version, state, card counts, brief ID, and a
  skipped flag;
- carries no outer model, no instruction, and no tools.

=strategy_agent/app.py= builds the app in a factory. Nothing runs at import
time: =agentplatform.init= lives inside =build_strategy_app=, so importing the
package contacts no Google Cloud service. The declared identity requests
=roles/datastore.user=, =roles/bigquery.dataViewer=, =roles/bigquery.jobUser=,
and =roles/telemetry.tracesWriter= — the handoff's trace-writer role, not the
broader legacy =roles/cloudtrace.agent=, which is now in the forbidden prefix
list alongside storage, Pub/Sub, and Memory Bank.

** Atomic persistence
Saving the brief, moving the session to its terminal state, and releasing the
lease are ONE store operation: =commit_strategy_session=, implemented with the
same signature as a single SQLite =BEGIN IMMEDIATE= transaction and a single
Firestore transaction.

This closes the crash window that would otherwise leave a stored brief whose
session is still =running= — a state that permanently blocks every retry for
that period. Either all three writes land, or none do.

Brief IDs are also now unique per session: =brf_2026w35-8xr31dpc=. The weekly
period alone is not a safe key, because a retry after a failed session covers
the same week and would collide with the abandoned attempt's write-once brief.
=BriefId= accepts the plain weekly form and an optional session discriminator,
so analyst-era briefs still validate.

** Error redaction
=strategy_agent/errors.py= is the single sanitizer. It reduces any exception to
a stage, a class name, and a curated reason drawn from a fixed table; it never
reads =str(exc)=. That matters because Pydantic's =ValidationError= renders
=input_value=, so a malformed model response, a claim statement, or a grounded
quote can otherwise end up inside a persisted session, lease, or log line.

An unrecognised exception class collapses to a generic reason, so a new
exception type cannot leak text simply by not having been considered yet.

** Model boundary
=strategy_agent/invoker.py= is the only place a strategy agent reaches a model.
=AdkAgentInvoker= runs one ADK turn through Vertex/Agent Platform ADC. It was
*not* exercised in this task. Every test and the synthetic session use
=ScriptedInvoker=, which returns pre-written structured payloads, so the entire
workflow runs with zero provider calls.

** Evidence consistency
=evidence_defect()= is shared by the context builder and the premise resolver,
so a claim can never be admitted to a session on evidence a card would then be
rejected for. Beyond canonical =delta@2=, a premise's evidence must satisfy:
- the Delta is =meaningful= — a noise Delta records that nothing durable
  changed and is audit and cost evidence, never a premise;
- the Delta's entity matches the claim's entity;
- the Delta's source matches the source recorded on the claim's evidence entry.

* Synthetic end-to-end session
Command: =just strategy-session= (report at =data/strategy_local_session.json=,
disposable store at =data/strategy-local/=).

The synthetic market has four canonical =delta@2= rows across three entities,
including one deliberately mirrored pair: =claude_code= publishing identical
sandbox text to =github_releases= and =website_changelog=.

Result:
- session state =completed=; 2 cards proposed, 1 passed, 1 rejected;
- manifest hash =3d02e2826cd47f3c50f5db92958ff1e419e545927d3dd714f0f6aa8016398481=;
- context 5,362 bytes / ~1,341 estimated tokens, well inside the 200,000-byte
  and 50,000-token budget;
- brief =brf_2026w35-<session>=, pinning exactly the two premise claim versions
  of the passed card;
- agent call order: =tycho_strategist=, =tycho_challenger=, =tycho_brief_writer=.

** The accepted conclusion
Spans =claude_code= and =codex= with two distinct source families, confidence
=likely= (ceiling from two confirmed premises), a competing explanation, and an
observable falsifier. The Challenger passed it; Python had already passed it.

** The rejected conclusion
Rejected by deterministic validation *before* the Challenger was consulted, for
four independent reasons:
1. =a cross-entity conclusion needs 2 distinct entities; got 1=
2. =a conclusion needs 2 independent source families; got 1 after mirrored-evidence normalization=
3. =conclusion asserts unsupported causation=
4. =conclusion asserts unsupported leadership=

The Challenger was invoked exactly once, for the surviving card only. The
rejected card remains in the session audit and its non-shared premise never
appears in the brief.
